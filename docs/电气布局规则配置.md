# 电气布局规则配置

将项目根目录的 `ClassPlacerRules.example.json` 复制为与 PCB 文件同目录的 `ClassPlacerRules.json`。插件运行时自动读取它；文件不存在时保持原有布局行为。

规则只处理**局部引脚关系**。源器件必须属于本次选择的 Class；目标器件必须已锁定或是该 Class 选择的中心器件，因此求解器不会把“靠近谁”建立在另一个可移动器件的旧坐标上。

## 规则类型

`pin_proximity` 是通用规则，适用于：

- 晶振到 IC 的 `OSC_IN` / `OSC_OUT` 引脚；
- 反馈电阻或补偿网络到稳压器 `FB` / `COMP` 引脚；
- 串联终端电阻到发送端或接收端；
- ESD 器件到已锁定的连接器；
- 栅电阻到已锁定的栅极驱动器或 MOSFET。

每条规则给出源器件、目标器件、双方参与测距的网络，以及最大引脚间距离（mil）。测量的是对应网络焊盘的最近欧氏距离，而不是器件中心距离。

`decoupling` 是兼容写法，会转换为同一类引脚近距规则；它额外校验电容是否具有指定的地网焊盘。

## 强度与优先级

- `severity: "hard"`：超过 `max_distance_mil` 即为无效候选，插件不会写回。
- `severity: "soft"`：允许超出上限，但距离会进入目标函数；它仍优先于中心聚集和视觉对齐。

总体优先级是：碰撞/锁定/硬电气规则 → 网络电气评分 → 总 HPWL → 中心聚集 → 对齐。

## 晶振示例

晶振通常至少需要两条规则：`X1` 的 `OSC_IN` 到 `U1` 的 `OSC_IN`，以及 `X1` 的 `OSC_OUT` 到 `U1` 的 `OSC_OUT`。负载电容应分别以同样方式贴近对应振荡网络引脚。不要只写“X1 靠近 U1”，因为那无法保证靠近正确引脚。

晶振、去耦、反馈和栅极回路宜使用 `hard`；串阻、ESD 等同时受机械位置影响的器件可先使用 `soft`，再在 AI 后处理阶段根据连接器和板边位置复核。

## 与 AI 后处理的关系

插件先保证本文件中的局部约束，随后 `.ai-handoff.json` 将这些功能块交给 AI。AI 默认只刚性平移功能块；如需移动受规则约束的成员，必须重新检查本文件的引脚距离，不得以板面压缩或视觉对齐为理由突破 `hard` 规则。
