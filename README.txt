Class Placer 0.4 — Component Class 批量布局原型
=============================================
本版替代旧版导出/计算/应用三步操作，不需要 EDA Agent。
需要 Windows、Python 3.10+（含 tkinter）、Altium Designer 脚本支持。
外部逻辑已自动测试；当前环境没有 Altium Designer，无法验证 AD 25 编译、DFM 加载及真实写回。
请首次在完整项目副本上验证，不要覆盖唯一一份设计。

完整的使用前置条件、结构/电气准备与布局后检查见：[docs/插件使用与布局前置准备.md](docs/插件使用与布局前置准备.md)。

一、原理图准备
每个目标元件可添加参数（作为默认中心）：
ClassName = LCD
CenterComponent = U2 C17
同一 Class 的所有 PCB 成员，其 CenterComponent 一致且非空时会自动作为默认中心。值可用空格分隔多个中心器件的 designator（例如 U2 C17）。
参数有效时，v0.4 选择窗只读显示这些中心器件，运行时直接采用它们，不需手选。仅参数缺失、冲突或无法匹配 PCB 位号时，才显示整类成员供按 Ctrl/Shift 手动兜底选择。
U2 必须在 LCD 类内。请先通过正常 ECO 将 Component Class 同步到 PCB。
参数从所属项目的编译原理图读取；不要求 CenterComponent 被当作普通 PCB 参数同步。
本版用编译后的物理位号匹配 PCB。多通道项目需填写物理中心位号；不自动猜测 U2_A/U2_B。
如果一个器件同时归属多个选中类，且会被移动，会拒绝开始，以免重复排布。
可只选择其中一个类；共享的锁定器件允许保留。

二、一次性安装
1. 将本包完整解压到固定文件夹，不覆盖旧版目录。
2. 双击 Setup.cmd。它只记录本机 Python 和工具所在路径，生成 ClassPlacer.pas。
   不安装 Python 包、不改注册表、不修改 AD 设置。
3. 出现 Setup complete 后，在 AD 中 File > Run Script > Browse，打开 ClassPlacer_030.PrjScr。
4. 移动工具文件夹或更换 Python 后，需再运行 Setup.cmd。
   请使用包含 tkinter 的 Windows Python；若安装失败，保留窗口中的完整错误信息。

三、正常使用（每次）
1. 激活属于已打开项目的目标 PCB。无需预先选择器件。
2. 运行 ClassPlacer.pas 下的 RunClassPlacement。
3. 工具自动读取 PCB、所属项目原理图参数和实际 PCB Component Class。
4. 自动打开外部 Class 选择窗：
   - 系统默认类、SuperClass 不参与布局。
   - 默认勾选全部非空的非系统类；每行只读显示原理图参数指定的中心元件。
   - 有效 CenterComponent 参数自动生效；仅缺失、冲突或无效时才可直接选择中心作为兜底，不必先改原理图。
   - 每类可选 keep / top / bottom。所有中心和锁定件不翻面，top/bottom 必须与所选中心当前所在层一致。
5. 按需取消勾选部分 Class，点击“布局并自动应用”。
   默认间距 12 mil、每类时间预算 5 秒，可在同一窗内调整。
6. 不再需要手动选择快照，不需要另点 Apply。
   全部选中类求解成功后，自动回到 AD 重新核对整板数据、中心参数和类成员，
   检查最终碰撞，保存位置与层恢复点，再一次性写入并回读坐标/层。
7. PCB 保持未保存。请检查焊盘、器件朝向并运行 DRC 后再保存。

四、布局范围与锁定器件
初始范围根据可移动器件数量、包围框尺寸、12 mil 等间距估算。
没有可行解时，每次扩大到前次半宽的 1.6 倍；最多 8 个阶段、半宽 20000 mil，
并受每类时间预算限制，避免无限搜索。
范围是算法搜索范围，不是 PCB 板框或 Room。
锁定器件（包括 M3 安装孔）始终保持原位，不受初始范围限制，仍参与避让。
所有中心器件的位置和朝向始终不变。多个中心器件会共同定义搜索范围与聚集目标。
若任一选定中心已由用户手工放置并锁定，该类外围器件仍以中心为聚集目标，但不再受 ClassPlacer Room／搜索边界限制；碰撞、间距和未选中器件避让仍然生效。
非选中 Class 中的器件不移动，并作为其他类的避让障碍。
已求解类的新位置会成为下一类的障碍，最后再做整板检查。
结果受选中类的处理顺序影响，不保证全局最短。
某一类在预算内失败，则整个批次不应用，不会先移动已经算好的前几个类。

五、进度、取消、错误
计算在独立 Python 工作进程，选择窗显示当前类、搜索范围和阶段。
进度条按已完成类数及当前类时间预算估算，不代表全局最优程度。
连续一段搜索无改善时可提前结束，不会每次都耗尽全部预算。
外部选择窗或 AD 等待窗均可取消；取消后不发布/应用新方案。
AD 开始实际写入后为一个不处理 UI 消息的短事务，期间不支持逐器件取消。
AD 读取过程有数量和 30 秒检查；无法打断单次阻塞的 AD API 调用或编译。
因此仍需在本机确认 AD 读取/写回兼容性，不能承诺 AD 端绝不暂时无响应。

六、运行文件与恢复
每次运行的文件自动存放在：
<PCB完整路径>.classplacer_jobs\<时间戳>.snapshot...
包含快照、worker.log、ad.log、status、plan、report.json、rooms.json、adstatus、restore。
原理图和 PCB 文件不会发送到网络。
正常完成后 report.json 记录每类范围扩展次数及布局前后内部网络 HPWL。
RestoreClassPlacement 读取同一 PCB 最近一次的恢复点，恢复该批次应用前的坐标、角度和层。
恢复依赖位号，仅用于同一 PCB、未替换的同一批元件；不是完整设计文件备份。
在恢复点之后如更换器件或重新布线，不应盲目恢复旧位置。
写回异常会尝试恢复原位置，但无法保证 AD 进程故障后的完整回滚；请检查再保存。

七、当前边界
支持顶层与底层的可移动成员；跨层切换仅对非锁定、非中心成员生效，并受最终碰撞检查保护。
最多 2048 个板上元件、65536 个联网焊盘、256 个非系统类。
采用保守的元件包围框避让，包括两面元件；不检查真实 courtyard、3D 机械干涉。
先优化类内网络的电气 HPWL（GND 降权），再压缩原始总 HPWL 和中心聚集项；不承诺实际布线全局最短。求解完成后会尝试对齐到已有行/列，但只有在电气 HPWL、总 HPWL 和中心聚集均不变差时才接受该美化调整。
不约束 PCB 板框、Keepout，不避让现有走线/过孔，不自动布线。
每个已选 Class 自动生成稳定命名的 Room 定义清单（ClassPlacer_<Class>）及最终包围盒，保存在 rooms.json，可审计和重放 AD 的 Component Class→Room 更新。锁定中心类会标记 room_enabled=false 和 follow_locked_center=true，后续 Room 更新不应对其外围器件施加限制。Room 原生对象创建/改形尚未在 AD 25 实机验收；首次请核对该清单或用 AD 的 Component Class→Room 功能生成实际 Room。
请用于未布线器件排布；电源输入/开关/反馈回路仍需按芯片手册审查。
